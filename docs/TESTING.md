## 帧率和设备边界

完整成功主流程的活跃样本约 162–165 FPS。后续 `browser-final-build.json` 的 1280×720 C1 回归出现过一个 56 FPS 活跃采样窗口，不能把结尾 165 FPS 当成全程稳定。排查发现自适应画质原先仅在低于 54 FPS 时减负，56 FPS 会留在不降级区间；现已改为低于 60 FPS 降低像素比，超过 75 FPS 才缓慢恢复。修复后再次实际跑完 900m，`browser-performance-retest.json` 的有效活跃采样范围为 **90–165 FPS**，低于 60 的有效采样为 0。该测试通过，不代表所有未来场景或所有设备的最坏帧保证；旧记录完整保留。

只读计数以约 2 秒窗口统计 requestAnimationFrame 帧率，包含正常 CPU/GPU 绘制与浏览器调度，不能代表每一帧的最坏耗时。首次测试历史中也曾有低于 60 的采样，发生在页面可见性、暂停和窗口切换的测试期间，不能直接证明这些现象是唯一原因。

实玩截图中场景通常约 70–110 次 draw call、约 2.7–3.6 万三角形。完整主流程采样可见实体和几何体数量保持在有限范围。实例化植被、共享模型、距离回收、每 240m 局部原点和自适应像素比均已启用。约一小时无尽测试为规则模拟；未执行一小时浏览器 GPU 压力测试。

**所有目标设备 60 FPS 以上仍是性能目标，不能宣称已在全部设备达标。** 本机桌面已测达到目标；844×390 手机横屏窗口、1024×768 平板布局及竖屏暂停属于视口验证，不是手机/平板硬件验证。iPhone 13 / Safari、骁龙 8 Gen 1 级 Android / Chrome、真实多点触控、移动浏览器工具栏变化和设备发热后的持续帧率尚未实机测试。触摸重复/取消机制已有单元测试，真实触屏手感仍需设备复验。

## 已知限制与交付范围

- 单人本地游戏，存档保存在当前浏览器，不含账号、云同步、联网排行榜。
- 音频需首次点击/按键解锁，使用本地 WebAudio 合成；不依赖音频 CDN。
- 需要 WebGL 与 HTTP 静态服务；直接双击 `dist/index.html` 的 file 协议不作为支持的启动方式。
- 全屏和方向锁定受浏览器能力限制；不支持锁定时仍可手动横屏游玩。
- 真机性能与连续一小时 GPU 压力测试尚未执行，以上结果不外推到所有设备。
