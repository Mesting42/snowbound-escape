# 高速人物清晰度修复

用户确认：人物大小保持原样，只改善边缘和细节。没有改变人物缩放、镜头缩放公式、前瞻距离、物理参数或操作规则。

## 代码中的影响因素

此前渲染倍率受 `devicePixelRatio` 上限约束：普通1×屏幕即使自适应参数为1.5，实际绘图仍只有1×；流畅模式甚至为0.8×，低分辨率结果放大后会让小人物边缘发虚。另外，120Hz物理位置直接用于任意刷新率渲染，相邻显示帧可能重复同一个位置，再突然前进一个物理步。它没有运动模糊滤镜，但高速时的跳动可能降低轮廓稳定性。这些是源码确认的影响因素，不是本轮实拍确认的唯一成因。

## 实现

- `src/render/quality.ts` 独立管理画质预算。普通屏幕也允许超采样：1280×720自适应初始绘图为1920×1080；精细模式最高2×。超采样提高边缘覆盖精度，不改变屏幕中的人物大小。
- 流畅模式保留1× CSS原生分辨率，关闭动态阴影并减少环境粒子，移除先降至0.8×再放大的路径。
- 自适应低于60FPS时，先关闭动态阴影并把环境粒子从180降到90；持续不足才以0.125步幅降低采样倍率，最低1×。恢复需连续四个大于80FPS的两秒窗口；具备更大余量时才恢复阴影，避免画质频繁抖动。
- 自动模式最高1.75×，精细最高2×；大视口分别按约400万/600万额外采样预算限制倍率，最低仍保留1×。高分辨率大屏的原生像素数量可能超过该预算，不能将其理解为严格GPU负载上限。
- `src/render/sampling.ts` 在前后物理姿态之间插值，主入口每个固定步前记录样本，渲染人物与跟随镜头使用同一呈现坐标。最多增加一个固定步（约8.33ms）的呈现延迟，不改变输入消费、碰撞、空翻结算或物理数据。
- 教学重练、检查点、暂停等离散状态直接采用当前位置；角度按最短弧插值，避免落地归一化造成整圈跳变。
- 只读诊断增加 `renderQuality`，提供实际绘图缓冲、采样倍率、阴影和粒子状态，供后续复验。
